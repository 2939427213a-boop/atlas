## 00 · Astra / What Astra changed for computer use
副标题：进步在边角上
时间：00:50–03:23

**一句话**：Astra 之前，Sol 已经很会用电脑。Astra 的进步在边角上：更快、更可靠、更对齐。这些恰恰决定人敢不敢放手。

### 要点
1. **Ari：更快**。同一个任务，它用的思考 token（thinking tokens）更少，所以平均更快。
2. **Ari：更会做创意活**。发布视频里，你一边说，它一边在 Microsoft Paint 里画。
3. **Ari：更可靠**。99% 和 97% 的可靠度，差别很难察觉，但很重要；他“更信任它一点”。
4. **James：更对齐**。按 system card，它更能抵抗 prompt injection（藏在网页、文件里劫持 agent 的指令），也更少做意料之外的操作。采购、对接供应商和客户这类敏感工作最需要这一点。

### 可视化
1. **四项改进**（`v00`，静态数字卡 4 格）：更快 · 思考 token 更少 ｜ 更会创意 · Paint 里边说边画 ｜ 更可靠 · 97% → 99% ｜ 更对齐 · 更抗 prompt injection。卡下小字：“前三项是 Ari 的个人体感（anecdotal）；第四项 James 引 system card。”
2. **X 原帖图**：`assets/x/x00_osworld_cost_2026-09-29.png`（OpenAI 2104986133004505373 第 3 张图：OSWorld 2.0 离线集，分数 vs 每任务成本。GPT‑6 Astra 最高约 73%，每任务约 9 美元；同日发布的 GPT‑6.1 Sol 约 71%，约 1.3 美元）。图注说明这就是 Ari 说“Sol 本身已经很会用电脑”的背景。[src:sol61]

### 讲者补充
- James：内部让 Astra 和 GPT‑5.6 对打电子游戏，Astra 每局都赢；网上有人让 Astra 约 30 小时打通 Fallout（背景：是 1998 年的 Fallout 2）[src:fallout]。

### 分析（整理者观点，非讲者原话）
- 推断：如果把可靠度理解为每一步的成功率，20 步的任务，97% 每步全程约 54% 成功，99% 约 82%。两个百分点，差出一倍的“放心”。

### 背景折叠（`details.rx`，summary：Astra、Sol、Terra、GPT‑5.6 是什么？）

## 01 · 两条线 / Consumer vs. enterprise computer use
副标题：消费端探路，企业端补课
时间：03:23–05:43

**一句话**：James：企业端的用例早就清楚，企业在追赶模型能力，关键是安全；消费端负责推前沿，找今天的软件做不到的新用法。

### 要点
1. **分工**：Ari 偏消费端，James 偏企业端。
2. **企业（James）**：大量用了 15–20 年的老软件，没有 MCP 工具，界面停在上一个十年，普通人都不太会用。已有公司给模型写 skills，教它用好这些软件。
3. **消费（James）**：Astra 快得多，所以能做新体验。
4. **消费（Ari）**：把日常烦人的事交给 agent，省下时间。例子是 dots：每个 dot 有自己的云端电脑和完整浏览器，能买东西、约理发。

### 可视化
1. **两条线**（`v01`，静态两栏 `.cmp2`）：
   - 企业：能力早就够了 → 企业在追赶 ｜ 难点：安全、管控 ｜ 例子：15–20 年的老软件、没有 MCP
   - 消费：推前沿 → 找新用法 ｜ 关键：速度 ｜ 例子：dots 买东西、约理发

### 背景（`div.ctx`）
- **MCP**（Model Context Protocol）：给 agent 接工具和数据的开放协议；前提是有人先为这个软件写好 MCP server[src:mcp]。
- **@ChatGPT（2026-08-25）**：ChatGPT Work 能用自己的电脑和浏览器登录网站，ChatGPT 看不到你的用户名和密码；举例有办水电、约 DMV 或护照预约、找医保内的医生。[src:signin]

## 02 · dots / How James runs his workday with dots
副标题：主动找事做的 agent
时间：05:43–08:06

**一句话**：James：dots 的价值在“主动”。它自己发现漏掉的事，也接得住每次形状都不一样的长期任务，并在云端和本地两台电脑之间做完。

### 要点
1. **主动补漏**：公司邮箱里的外部会议邀请不会进日历，他因此错过好几个会。现在 dots 会问：“收件箱有个邀请，日历上没有，要我在 Gmail 里接受吗？”
2. **给目标，不给步骤**：以前他用 automations 和 Codex 写定时任务，每 30–60 分钟扫一遍 Slack。现在只说：“汇报线上的人说了什么就告诉我；有人给产品提尖锐反馈，你自己判断。”
3. **两台电脑**：dots 既能控制他的本地电脑，也有自己的云端电脑。

### 可视化
1. **一条反馈的处理**（`v02`，静态前后对比 `.vs`）：
   - 以前（人做 6 步）：判断哪条反馈重要 → 看反馈 → 打开 Sentry → 下载日志 → 喂给 Codex → 问它的看法
   - 现在（dots）：一个目标 → dots 驱动浏览器登录 Sentry、拉日志、分析 → 给他结论
   - 图注：Sentry = 程序报错监控服务，用户报 bug 时常附 Sentry 日志。
2. **X 原帖图**：`assets/x/x02_dots_2026-10-01.jpg`（OpenAIDevs 2105708732323909827：dots 演示视频封面）。图注：OpenAI 2026‑09‑29 发布 dots，“powered by GPT‑6 Astra”，定位是常驻（always-on）agent；面向 Pro、Business Premium、Enterprise 用户[src:dots]。

## 03 · 超人 / When computer use becomes superhuman
副标题：比专家快的那一天
时间：08:06–10:01

**一句话**：Ari：速度决定 agent 值不值得用。它已经比普通人快，正接近比专家快；到那时，手动能做的事默认都会交给 agent。

### 要点
1. **他的说法**：OpenAI 有“最快、最便宜、最可靠”的 computer use 产品，而且还能走得更远。
2. **为什么在乎速度**：后台任务慢点没关系；但你要盯着它确认、或后面的事要等它时，慢会让人觉得“不如自己做”。
3. **现状**：已比普通人用电脑快；接近 superhuman，即比专家（“比如这张桌上的我们”）还快。他称之为“巨变”（sea change）。
4. **多模型、多价位**：便宜的模型 computer use 也在快速变好；以后不同任务会用不同模型，选择更分散。

### 可视化
1. **速度标尺**（`v03`，静态横轴）：普通人 ✓ 已超过 → 专家 · 接近中 → superhuman。标尺下：到那时，“除非你想自己做，默认交给 agent”。
2. **X 原帖图**：`assets/x/x03_cost_case_2026-10-26.jpg`（a16z 2114836977472467320：把 Ari 这句话配上 8 月文章的成本图。每小时成本：computer-use agent 6–8 美元，常见 3–15；印度外包约 10；美国后台人工 30–45，含福利和管理费用）。[src:a16zpiece]

### 分析（整理者观点，非讲者原话）
- 换个角度看：快过专家后，问题从“它能不能做”变成“我还要不要盯着看”。这正是下一章。

## 04 · 放手 / How much autonomy to give agents
副标题：盯不过来之后，怎么管
时间：10:01–11:36

**一句话**：James：agent 快到人盯不过来时，要能调“人在环中”的多少，还要能事后审计。Astra 一起推出了企业管控，还有一个逐步审核动作的模型 Guardian。

### 要点
1. **慢的悖论**：慢的时候你能看着它，但只能交给它“值得坐着看”的事，所以反而低效。
2. **快了之后**：人看不过来，企业需要两样东西：控制 human-in-the-loop 的程度，和 auditability（事后可查）。
3. **企业管控**：随 Astra 推出。企业可选全部自动批准，也可要求人批准。
4. **Guardian**（他说 app 里叫 auto-approve）：一个很聪明的模型，审核 agent 的每一步，判断是否安全、是否符合最初的意图。
5. **因人而异**：消费者可能只想“全做了、别问我”；企业自己定。agent 越超人，控制越重要。

### 可视化
1. **审批旋钮**（`v04`，静态三档刻度）：每步都要人批准 ｜ Guardian 模型逐步审核 ｜ 全部自动。两端标注：企业可以选 · 消费者常想要。刻度下：越快 → 越需要审计。

### 讲者补充
- 主持人（Seema）：雇主对效率很兴奋，也担心放出来的是什么。

## 05 · 广告 / What agents mean for ad-supported sites
副标题：agent 看广告，不算钱
时间：11:36–13:51

**一句话**：James：公司内部的软件，自动化没有争议；难题在开放网络。靠广告的网站收不到 agent 的“曝光”收入，愿意拥抱 agent 的网站在采用 WebMCP 这类标准。

### 要点
1. **公司批准的软件**：“100% 欢迎”自动化。
2. **开放网络分两类**：
   - 商业模式冲突：广告主、靠广告的出版商。agent 产生的广告曝光多半不算真实收入。OpenAI 在和合作伙伴团队一起想办法。
   - 欢迎 agent：采用让人和 agent 一起用网站的标准，例如 WebMCP；OpenAI 已在 app 内浏览器里支持它。
3. **他的设想**：agent 做繁琐的部分，把“逛”留给人。他自己仍喜欢逛购物网站、挑酒店和机票；挑好了，再交回 agent 填卡付款。

### 可视化
1. **一次购物，人和 agent 分工**（`v05`，静态箭头链）：agent 做繁琐部分 → 人逛、挑（酒店、机票、商品）→ agent 填卡、付款。底注：WebMCP 让网站自己仍是界面，不必变成 API。
2. **X 原帖图**：`assets/x/x05_webmcp_2026-10-26.png`（ChromiumDev 2114776553481445523：MCP 与 WebMCP 对照表）。图注：MCP 把 agent 接到你的后端服务；WebMCP 让网页自己向 agent 提供工具，只在页面打开时可用，用的是用户当前的登录状态[src:webmcp]。

### 背景（`div.ctx`）
- **WebMCP**：Google 和 Microsoft 提出的浏览器标准提案（细节待 context_facts）[src:webmcp]；2026‑10‑20，ChatGPT 桌面版为 MCP Apps 打开了 WebMCP[src:webmcp-chatgpt]。

### 分析（整理者观点，非讲者原话）
- 换个角度看：WebMCP 让网站保住自己的页面和用户关系，agent 来了也不必被“绕过去”。

## 06 · 通用接口 / Computer use as the universal API
副标题：先问“能不能交给 agent”
时间：13:51–17:21

**一句话**：computer use 不需要谁先做适配，它像人一样操作任何应用。James 称它是模型“为了把事做成”的通用 API：任务越复杂，越可能用到它。

### 要点
1. **James 的习惯**：有任务先想“能不能让 agent 做”。例外：发给别人的消息，他想让它像出自自己。
2. **需求模糊也行**：Astra 推出了 flexible input。它会先问你细节；你没及时回答，它就自己找上下文继续做。重复的工作流，像写产品 spec 一样写清要求。
3. **Ari：普适**。不用谁先写 connector 或 MCP server；它像人一样用应用，agent 就拥有你的全部能力。他在刻意培养“先交给 agent”的冲动。
4. **James：不再区分**“是不是 computer use 任务”。只有简单到点两下就完的事他才自己做；等它更快，这些也可以用语音让它做。

### 可视化
1. **三种接入方式**（`v06`，静态表）：
   | 方式 | 谁要先做事 | 能用的软件 |
   |---|---|---|
   | API | 软件方开放接口 | 有 API 的 |
   | MCP | 有人写 MCP server | 有 server 的 |
   | computer use | 不用 | 任何有界面的 |

### 分析（整理者观点，非讲者原话）
- 换个角度看：通用的代价是慢和贵。API 一次调用的事，computer use 要看屏、点很多步。所以第 03 章的速度和成本才是关键。

## 07 · 信任 / Getting enterprises to trust agents
副标题：确定性护栏，看得见的光标
时间：17:21–20:22

**一句话**：James：让企业放心靠两层：管理员能设的确定性管控，和把对齐评测摆出来。Ari：产品设计也在建立信任。

### 要点
1. **主持人（Seema）的疑问**：人虽然慢、会出错，但受过训练、可以问责。
2. **第一层：确定性管控**。就算模型最对齐、比多数人更会防 prompt injection，管理员能说“这类任务、这类数据太敏感”时，企业才有安全感。
3. **第二层：证据**。把内部和第三方的对齐评测给管理员看。
4. **Ari：设计建立信任**。想看时总能看到光标，它的动画很有趣，“看着不无聊”。普通用户第一次用某个应用或网站前，它会先征求许可（视模式而定）。先有一个建立信任的时刻，之后越来越放心。

### 可视化
1. **两层**（`v07`，静态结构图）：
   - 第一层 · 确定性管控：沙箱（agent 能用哪些应用、哪些网站）｜人在环中（上传、下载要人批准；去新网站要人批准）——“都是旋钮，企业自己调”
   - 第二层 · 证据：内部 + 第三方对齐评测

### 讲者补充
- 主持人（Fabrizio）：“Codex 的光标太可爱了。”小细节，但看着它操作会让人有信心。

## 08 · 无聊 / Why the best use cases are the boring ones
副标题：Boring is opportunity
时间：20:22–25:37

**一句话**：James：最好的企业用例很“无聊”：在 ERP、CRM 这些记录系统之间搬数据、对账、下单。创意类工作（电路、建筑、游戏设计）是下一步。

### 要点（表）
| 类别 | 例子 |
|---|---|
| 企业的繁琐流程（James） | 采购：每年订实验室设备，千行表格→运营录入采购软件→采购团队联系供应商，全程可自动 ｜ 财务：月底多本账对账，很多财务软件没有 API ｜ 销售：找潜在客户、录入外联软件 ｜ 市场调研 |
| 更有野心的工作（James） | 视觉设计、电路设计、建筑、硬件工程、游戏设计；企业现在想得少 |
| 消费端的杂事（Ari） | 填 DMV 表、退订邮件 |
| 以前没时间做的事（Ari） | 他维护财务和备餐的表格，用的是小众的 Apple Numbers；当私教的朋友给每个客户做定制内容 |
| 第三类（Ari 最期待） | 用语音和整台电脑交互；软件的形态会因此改变 |

### 可视化
1. **一次采购**（`v08`，静态前后对比）：各团队填千行表格 → 运营录入采购软件 → 生成订单 → 采购团队联系供应商 ⇒ computer use 全程做。
2. **X 原帖图**：`assets/x/x08_astra_pcb_2026-09-03.jpg`（ChatGPT 2095597504226267333 的第 1 段视频封面：Astra 发布时的演示画面，一块电路板的布线图和 3D 渲染）。图注：James 说电路设计这类工作是下一批用例。[src:astra]

### 讲者补充
- James 的市场调研：他业余做羽毛球视频标注软件，让 agent 去匹克球、壁球、网球的同类软件注册、试用、截图、给反馈，再改进自己的 app。
- 主持人说“boring is opportunity”，James 接话：所有记录系统（system of record）都是。

## 09 · 界面 / Why UI isn't going away
副标题：软件便宜了，就得更好
时间：25:37–32:38

**一句话**：老软件会长期存在，computer use 正好能操作它们；做软件也变得便宜，所以界面不会消失，反而会更个性化、更好用。

### 要点
1. **主持人（Seema）的问题**：企业会留着 30 年前的笨重 ERP、让 agent 在上面操作？还是 AI 原生的新软件取而代之？
2. **Ari：两者都会长期存在**。生产环境里很多软件是 10–40 年前写的，不会一夜消失。computer use 会逼软件更适配 agent，WebMCP 就是例子。
3. **James：不想要“没人用界面”的互联网**。他给妻子做了五子棋（Omok）战术训练器，按她喜欢的学法定制。复盘总结可以交给 agent，但下棋本身要人练。
4. **Ari：人天生偏爱直接操作**（direct manipulation）。过去软件为几百万到几十亿人设计；以后可以只为 100 个人、甚至 1 个人设计。
5. **主持人（Fabrizio）的两个桶**：消费端看重乐趣和学习；B2B 让 agent 执行，人设目标、看审计日志（“这笔款为什么付了？”）。这仍需要界面。

### 可视化
1. **新软件与老软件并存**（`v09`，静态分层图）：人 → 新界面（为 1 人或 100 人设计）→ agent → computer use → 老软件（10–40 年前写的 ERP 等）。旁注：Ari 期待的新软件——界面传统，底下是 agent，有的 agent 再用 computer use 操作老软件。
2. **两个桶**（同一卡片下半，`.cmp2`）：消费 · 乐趣、学习，人要自己用 ｜ B2B · agent 执行，人设目标、看审计。

### 讲者补充
- James：他们内部叫“共享智能层”。如果每个网站都有自己的 agent，又不和你的 agent 对话，世界会很碎。接下来几个月要看它们怎么接上。

## 10 · 创业 / Advice for founders building on agents
副标题：深懂一个行业的复杂流程
时间：32:38–37:31

**一句话**：实验室做不完所有事。James：创业公司的机会在深懂某个行业的复杂流程，用 computer use 串起分散的软件，再包装成客户用着舒服的产品。

### 要点
1. **Ari：先想清形态**。小团队想更高效地用现成软件 → 坐到 ChatGPT 前协作；产品本身要操作现有软件 → 在云端机器上用 API 跑 computer use。后者要设计人何时介入：出错时告诉你？成功时？还是汇总，免得你被一堆会忽略的通知淹没。
2. **James：还有机会**。两人加入 OpenAI 前都是创业者。OpenAI 有几千人，仍然人手紧张。深懂一个行业（监管、go-to-market、怎么服务客户）就还有绿地；今天的护城河是速度。
3. **扩散慢的垂直行业**：餐饮集团就是例子（见下图）。
4. **旧金山之外**：普通企业要过四道坎（见下图）。

### 可视化
1. **一家初创公司给餐饮集团做的事**（`v10`，静态箭头链）：拍后仓照片 → 视觉模型按明天的客流预估缺什么 → computer use 去采购软件下单 → 进 ERP 按去年同期客流调排班。
2. **四道坎**（同卡片，数字卡 1–4）：知道工具能做什么 → 把工具连对 → 部署 → 持续服务。上方一句 James 原话转述：在旧金山，人们会想“为什么不直接装 Codex 让它做？”

## 11 · 一致 / Making computer use feel coherent
副标题：四个浏览器，互不相通
时间：37:31–40:57

**一句话**：下一步是更快、更会实时协作、更主动；也要把散在各处的浏览器和电脑，统一成普通人能理解的一套体验。

### 要点
1. **Ari：下一步**。更快、做到 superhuman、把语音和屏幕等多模态输入输出揉在一起。现在的产品偏后台（交代任务、你去忙别的），以后会有更多实时协作。
2. **James：四处分散**。Chrome 扩展用你 Chrome 里的密码管理器；桌面 app 的内置浏览器是另一套 cookie 和密码；dots 的云端电脑又是一套；ChatGPT Work 还有云端浏览器。普通用户会问：为什么有四个互不相通的浏览器？
3. **James：一个悖论**。computer use 本是最容易懂的 AI 产品（AI 在用你的电脑），但状态和位置太多，实现细节漏给了用户。他下个季度的目标：做到“consumer grade”、更连贯。
4. **Ari：主动性**。现在你得记得用它、想好怎么用、说服自己改习惯。他希望 agent 适应你，而不是你适应它；目标仍由人设定。

### 可视化
1. **四个浏览器**（`v11`，静态四格 + 汇聚）：Chrome 扩展 · 你的 Chrome 密码 ｜ 桌面 app 内置浏览器 · 另一套 cookie 和密码 ｜ dots 云端电脑 · 又一套 ｜ ChatGPT Work 云端浏览器。四格之间画“互不相通”，下方汇到目标：“一套连贯的体验”。

### 背景（`div.ctx`）
- **@ChatGPT（2026-10-15）**：ChatGPT 开始能用你在 Chrome 里的标签页。在 Chat 里只能看；在 Work 里能控制标签页，发消息、填表、下载文件[src:chrome]。

### 分析（整理者观点，非讲者原话）
- 换个角度看：“四个浏览器”其实是四套登录状态。agent 在哪儿有你的身份，就只能在哪儿干活。

## 12 · 拐点 / Computer use's scaling moment
副标题：从桌面到每个人的手机
时间：40:57–44:14

**一句话**：模型今年才变得好用，产品最近两个月快速增长；下一个拐点是云端电脑，把 computer use 带给只用手机的普通人。

### 要点
1. **Ari：曲线**。6–9 个月前做这些产品时几乎没人用；今年早些时候模型突然变得擅长这类任务；最近两个月产品“疯长”。但只有一部分用户在用，还很早。
2. **James：Atlas 的教训**。他 1 月加入 OpenAI 做 Atlas 浏览器，“RIP Atlas”。在 Atlas 里，agent 功能不是卖点：多数人把它当普通浏览器。后来浏览器和 browser use 被放进所有已有 agent 用法的产品，周增长像 YC 公司。
3. **James：下一个拐点是云端**。桌面仍是 power user 的东西，多数人用手机。要给每个人一台不用懂怎么用的强大电脑。
4. **Ari 收尾**：computer use 正处在规模化时刻，消费端和企业端同时。

### 可视化
1. **时间线**（`v12`，静态，标“背景”）：2025‑01 Operator ｜ 2025‑10‑21 Atlas 发布 ｜ 2026‑01 James 加入、做 Atlas ｜ 2026‑08‑09 Atlas 停止服务，功能并入 ChatGPT Work ｜ 2026‑08‑10 a16z 文章 ｜ 2026‑09‑03 GPT‑6 Astra ｜ 2026‑09‑29 dots、GPT‑6.1 Sol ｜ 2026‑10‑15 Chrome 里的 computer use ｜ 2026‑10‑26 本期上线、GPT‑6.1 Terra。（日期全部按 context_facts 核对）
2. **X 原帖图**：`assets/x/x12_osworld_2026-08-10.jpg`（a16z 2086832770895290624：OSWorld‑Verified 最佳成绩一年从约 42% 到 85%，人类基线约 72%；数据截至 2026‑06，早于 Astra）。图注：这就是 Seema 说的 8 月那篇文章[src:a16zpiece]。

### 分析（整理者观点，非讲者原话）
- 推断：Atlas 说明，用户为“浏览器”装浏览器，不为 agent 装。agent 能力要放进人们已经在用的入口。
